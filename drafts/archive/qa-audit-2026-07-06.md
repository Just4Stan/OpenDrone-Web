## 3 · UX findings by priority

### P1 - looks broken / blocks trust

1. **Related-products rail leaks real prices while the shop is locked.**
   Every PDP, both viewports, both themes. `€69.00 / from €35.00 / €22.00 / €6.00`
   under RELATED HARDWARE while the whole rest of the site (cards, pods, feeds,
   JSON-LD) is price-stripped.
   Cause: `app/components/RelatedProducts.tsx` - line 104 computes
   `comingSoon` and uses it to gate quick-add (line 116), but the price block at
   line ~186 only checks `priced = parseFloat(min.amount) > 0`.
   Fix: `{priced && !comingSoon ? … : <span>&nbsp;</span>}` (and keep the SOON
   badge treatment consistent with `ProductItem`).

2. **Notify-at-launch failure is silent.** When `POST /newsletter` returns 400
   (Turnstile fail-closed), the form shows no message at all - the `[role=status]`
   region stays empty (verified 1.2 s after response; screenshot
   `shots/e2e-notify-retry.png`). The launch list is the only CTA the locked shop
   has; a silent failure eats signups. Reproduce: submit with no Turnstile token.
   Check the `NewsletterSignup` fetcher error path (`app/components/NewsletterSignup.tsx`,
   status regions at ~lines 228/246) - the 400 JSON body does contain the message.
   (Dev-env caveat in runbook: on localhost the widget never renders, so every
   submit 400s - but the missing feedback is a code path bug regardless.)

### P2 - visibly unpolished

3. **`/open-source` desktop wastes the right half of the page.** At 1440 (and
   1024) the content is a single ~490 px monospace column; the right ~60 % of the
   canvas is empty for ~2300 px of scroll. Mobile reads fine - the desktop layout
   is just the mobile column left-aligned. Either two-column it (text + sticky
   figure/nav rail like the PDP) or center with a wider measure.
   `shots/open-source-desktop-dark.png`.

4. **PRE-LAUNCH badge overlaps interactive content at 1440×900.** The fixed
   bottom-right pill sits on top of the PDP notify form's consent line - it covers
   "I agree to receive updates … Privacy." including the checkbox/link at common
   scroll positions (`shots/e2e-notify-retry.png`). Same badge covers grid-card
   content in corners elsewhere. Give it a dismiss, shrink on scroll, or offset it
   above the content edge - it must never sit on the one form pre-launch visitors
   are asked to use.

5. **Light-mode gold fails contrast.** Measured: `--color-gold` on `--color-bg`
   = **2.78:1**, `--color-on-accent` on gold = **3.00:1** (dark mode: 7.69 both).
   Gold-filled buttons (SHOP / SUBSCRIBE / NOTIFY ME) and gold text links are
   below AA (4.5:1) in light mode. Darken light-mode `--color-gold` (~`#8a6410`
   territory for text use) or bump `--color-on-accent` ink darkness.
   Values in `partb-metrics.json` → `contrast-light`.

6. **Mobile PDP gallery dots are 4–6 px tall.** `.board-deck-dot` hit rects
   measured 79×4 – 79×6 px (all PDPs, 390 px). Swipe exists, but the only visible
   pagination affordance is untappable. Pad the hit area to ≥40 px (visual bar can
   stay thin).

7. **`/account.data` 400 on every pageview** (see console inventory).

8. **404 page has an empty `<title>`** (and no H1). Tab reads the raw URL;
   history/SEO gets nothing. Add meta to the catch-all route
   (`app/routes/$.tsx`) - "404 · Signal lost | OpenDrone" fits the OSD bit.

9. **Dark catalog mixes white-background frame renders with dark board renders.**
   OpenFrame 5"/3" cards are bright white tiles in an otherwise dark grid - the
   single most jarring inconsistency in dark mode (`shots/catalog-desktop-dark.png`;
   also the OpenFrame related-card on PDPs). Known deferred asset task
   (transparent/dark frame renders) - re-flagging because launch screenshots will
   be dark-mode.

### P3 - nice-to-have

10. `--color-text-dim` measures 3.35–3.62:1 on bg/card in both themes - fine for
    large/decorative text only; audit that it never carries body-size copy.
11. **Reduced-motion isn't fully honored:** the PRE-LAUNCH banner dot pulse
    (`.placeholder-banner__dot::after`, app.css ~13464) has no
    `prefers-reduced-motion` twin - 1–2 animations keep looping (PDP measured 2,
    catalog 1). Add it to one of the existing reduce blocks.
12. Support page H1 is `open<br/>a` → textContent "opena" (feeds AT/SEO
    extractors the typo). Add a space before the `<br />` in
    `app/routes/support.tsx` line ~132.
13. Cart hover preview: the drawer's own "CART" heading slides underneath the
    z-raised header while in preview mode - clipped text visible at the top of
    the drawer (`shots/e2e-cart-hover-preview.png`). Pad the drawer header down
    while `html[data-cart-preview]` is set.
14. Search results don't show coming-soon state - product rows are the only
    product surface with no SOON marker (catalog, pods, PDP all have it).
15. `/llms.txt` lists firmware-donation tiers with € amounts + variant IDs while
    everything else is price-stripped, and donation variants are permalink-able.
    Probably intentional (donations aren't products) - confirm.
16. Spacing tokens are half-adopted: 88 `var(--sp-*)` usages vs 138 literal
    px paddings/margins in `app.css`. Rhythm is visually consistent on the core
    routes; this is debt, not a visible break.
17. Contact/support: the Discord "ALT PATH" tile is half-empty next to the taller
    sign-in card - bottom ~40 % of the tile is dead. Let it size to content.
18. Home: the "Who's incutec?" hint chip appears on first scroll and then stays
    pinned under the logo for the entire scroll journey, both themes. If it's a
    hint, let it dismiss after a few seconds or after the first pod interaction.
19. Newsletter consent checkboxes are 20×20 (footer + notify form). Common, but
    below the 40 px guidance; padding-based hit area would fix it invisibly.
20. Font preloads (`jetbrains-mono-Regular`, `tokyo-regular`, `inter-var`)
    warn "not used within a few seconds" on content-light pages - check the
    `as`/`crossorigin` attrs and whether tokyo/jetbrains are needed above the fold.

### Explicit passes (checked, no finding)

- **Focus-visible:** 30-tab walk on home, catalog, PDP - every focused element
  had an outline or focus box-shadow. Zero missing rings.
- **Horizontal scroll:** none at 390 / 1024 / 1440 on any audited route.
- **Grid image aspect consistency:** every product-grid image measures 1.00
  aspect. Ghost tiles (hardware kit, spares, antenna, strap) are consistent and
  read well in both themes.
- **Motion budget:** steady-state ≤2 looping animations in a viewport
  (banner dot + wordmark sheen); count-ups and blur-up reveals are one-shot.
  Within the ≤2 budget.
- **One H1 per page** everywhere except 404 (see P2-8). Home's H1 is the hero
  wordmark with `aria-label="OpenDrone"` - fine.
- **Heading/eyebrow system** (`FILE 0x` eyebrows, page-title scale, numbered
  sections) is consistent across PDP / support / open-source / catalog. The
  engineering-doc language holds up; no shadow-soup, hairlines consistent.
- **Dark/light parity:** all audited routes theme correctly; no stuck-dark
  literals found on-screen (Discord panel intentionally dark per CLAUDE.md).
- **Cart drawer + hover preview interaction model** is genuinely good: non-modal
  peek, focus untouched, pin-on-interact upgrades to modal. Matches the council
  design intent.
